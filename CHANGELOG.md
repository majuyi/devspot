# Changelog

All notable changes to this project are documented here. Format: Keep a Changelog.

## Unreleased

- Specification set, ADRs, CLAUDE.md, skills and the M0 workspace scaffold.
- ADR 0015 accepted: Apache-2.0. Generated JSON Schema in docs/schema is excluded from Biome so builds leave the tree clean.
- First Prisma migration (`20261009000000_init`), generated offline from the schema.
- M0.1: dependency rule now enforced in full by Biome (fetchers could import `@devspot/db`, web could import the engine); `ci` script added (`pnpm run ci`).
- M0.2: `snapshot.schema.json` now validates both weekly release files (`SnapshotFile`); every schema has a valid and an invalid test; a test fails if `docs/schema/` is stale. Docs use the code's schema names.
- M0.3: `prisma generate` and `validate` no longer need `DIRECT_URL`, so `pnpm check` runs from a clean clone; CI fails on schema changes without a migration (`migrate:check`); missing `DATABASE_URL` throws `MissingDatabaseUrlError`.
- M0.4: 10 seed organisations, each source URL and robots.txt checked by hand on 2026-10-09 (Paystack, Ingressive for Good and AltSchool are `manual`; GSoC moves to its blog feed). `registry:check` and `db:sync-registry` share `validateRegistry`; sync validates everything before writing. CI asserts a second sync is a no-op.
- M0.5: `pnpm check` now runs `prisma validate` (in the `db` build). CI actions bumped to checkout v7, setup-node v7, cache v6 (Node 24 runtime); Node version read from `.nvmrc`.
- M0.6: `registry/LICENSE` (CC0 1.0) for the registry the docs already called CC0. SECURITY.md points to GitHub private vulnerability reporting (now enabled); a `security@` address follows with the domain in M5.1. CONTRIBUTING marks engine and web commands that arrive in M1 and M2.
- M1.1: `@devspot/engine` package with `HttpClient`: per-host rate limit (Crawl-delay honoured), 20s timeout, retries with jitter on 5xx and network errors, robots.txt cache with RFC 9309 status handling, redirects checked hop by hop, typed errors.
- M1.2: fixture record and replay. `pnpm engine record` and `pnpm engine replay [--update]` (sources read from the registry YAML); credential scrubbing that refuses bodies with secrets; `UnexpectedNetworkAccess` and a global no-network dispatcher in engine tests; root `engine` script no longer passes a literal `--`.
- Fix: `pnpm check` (and so CI) now runs Biome. It called `turbo run lint`, which ran nothing because no package has a `lint` script. `.claude/settings.local.json` is git-ignored.
- Registry: AfriLabs (Abuja), blog feed. Verified 2026-10-13.
- Spec: `/admin/new` for hand-entered opportunities (manual sources had no way in before `/submit` in M4) and an All tab in `/admin`, so published items can be found and corrected (the runbook relied on it). M2.10 check updated.
- Registry: CcHUB (Lagos), blog feed. Verified 2026-10-13.
- M1.3: feed fetcher (feedsmith 2.9.6 for RSS, Atom, RDF and JSON Feed) with conditional GET (`validators` in and out of `FetchResult`; 304 means no items); HTML to text that keeps paragraph breaks and lists, links in `meta.links`. `FetchFn` returns `FetchResult` as `04` §1 says. Fixtures and golden output for gsoc, afrilabs and cchub; a golden test replays every fixture and fails when a feed source has none.
- `Source` gets `include`, `etag` and `lastModified` columns (migration `20261013000000_source_columns`). Sync no longer packs `include` into `notes` as JSON, and the engine has somewhere to keep feed validators that sync will not overwrite.
- Registry: Chevening, fellowships sitemap. Verified 2026-10-13.
- M1.4: sitemap fetcher: urlset or one level of index, `include` glob, `knownUrls` from the caller, the 20 newest pages per run, page errors skipped and reported. Readable text via @mozilla/readability on linkedom, then the shared HTML-to-text. Fixture and golden output for chevening/fellowships.
- M1.5: `Adapter` contract (`src/adapter.ts`), `fetchers/html.ts` for `html` and `api` sources (adapters listed in `src/adapters/index.ts`, output checked against `RawItemInput`). Adapters for HNG (the internship page as one item, past cohorts and alumni sections dropped) and Devpost (open and upcoming hackathons from its listing API, 40 a page). Fixtures for both; the golden test fails if an adapter has no fixture and names the four registry adapters not yet written (bamboohr, bevy, mlh, outreachy).
- Dev: `DB_PORT` in `.env` sets the host port of the compose database, for machines where another Postgres has 5432. Fix: `pnpm db:migrate` and `pnpm db:sync-registry` now read the root `.env` that CONTRIBUTING describes; they looked in `packages/db` and found nothing.
- M1.6: dedupe. `canonicalizeUrl` and `contentHash` (whitespace and "last updated" dates ignored) with table tests; `upsertRawItems` creates, bumps or replaces `RawItem` rows by `(sourceId, canonicalUrl)` and returns only new and changed items, tested against the Docker database (skipped without `DATABASE_URL`, required in CI). Fix: the sitemap fetcher compared raw sitemap URLs with canonical `knownUrls`, so a URL with a trailing slash would have been refetched every run.
- Devpost adapter: online hackathons only, and each new hackathon's own page for its deadline (with time zone) and "Who can participate", excluded countries included. At most 10 new per run; known URLs are skipped, as in the sitemap fetcher.
- M1.7: rules extractor (`src/extract/rules.ts`, dates in `src/extract/dates.ts`): kind, deadline (fixed, rolling, multiRound, unknown) with stated time zones, start and end for events and bootcamps, location, venue, verbatim requirements, apply URL, tags, regions, summary, overall confidence. Date-only deadlines mean 23:59 in the stated zone, else Lagos time (decided 2026-10-13). `pnpm engine eval` on 20 hand-labelled items from the fixtures: kind 92%, deadline 100%, location 78%, no false publishes, no eligibility words.
- M1.8: `validateDraft` and `load`, the only writer of `Opportunity`: `identityKey`, slugs with a 4-character suffix on collision, the publish rule, reviewed rows that only ever gain `lastVerifiedAt`, and duplicates that wait in review. Invariants 3, 4 and 6 tested, against the database where it matters.
- Items with no kind or location now go to review rather than being dropped at validation (`kind` and `locationMode` are nullable on `Opportunity`; the publish rule needs both). A `Location:` or `Venue:` line scores 0.85, so a stated location can pass the 0.75 threshold. An update now refreshes kind and location too, so a row can never publish with them empty.
- M1.9: `pnpm engine verify [--all]` closes published opportunities on a past date, a 404 or 410, or a closed notice on the page, and otherwise stamps `lastVerifiedAt`. Health counters, source state (`sourceHealth` in `packages/schema`) and the run summary, ready for M1.10 to call.
- M1.10: `pnpm engine run [--source] [--org] [--dry-run] [--limit]` and `pnpm engine health`. One failing source never stops the run; exit code 1 when a source turns `erroring`. Sources with an unwritten adapter are skipped and logged. Registry sync moved to `syncRegistry` in `@devspot/db`.
- M1.11: production Supabase project (London) with the `engine` role. Workflows `engine.yml` (every 6 hours: run, then verify), `migrate.yml` (migrate deploy, then `grants.sql`), `backup.yml` (weekly encrypted `pg_dump`) and `keepalive.yml`. `grants.sql` also removes Supabase's default `anon` access to public tables.
- Source item filter (`filter` in the registry, `Source.filter` in the database): job boards keep listed departments or title keywords and drop senior titles before anything is stored (docs/04 §1).
- `bamboohr` adapter for any BambooHR careers board; Flutterwave's careers source now runs, filtered to tech roles.
- Rules extractor: a stated location it does not recognise no longer falls back to a city named elsewhere in the text or to the organization's city.
- `workable` adapter for any Workable board; Kuda added. The item filter gained `countries`, and `seniority: early` also reads a board's stated level.
- `zindi` adapter and Zindi added: open data science and AI competitions.
- Dates: an ISO time with `Z` or an offset keeps it (it was read as Lagos time, an hour out).
- `bevy` adapter for Google Developer Group chapters on gdg.community.dev; GDG Lagos runs, GDG Ibadan added. `utcLine` moved to `fetchers/util.ts`.
- M1.12: registry at 26 organizations (Paga, Chowdeck, Kuda, FairMoney, Renmoney, Zindi and GDG Ibadan, Port Harcourt, Enugu, Kano, Uyo, Calabar and Ilorin added); 20 yield opportunities in production.
- `mlh` adapter: online and hybrid hackathons from MLH's season page; Major League Hacking now runs.
- `outreachy` adapter: the current round from `/apply/project-selection/`, with the initial application deadline as the deadline. Every registry source now has an adapter and a fixture.
- M1 gate passed: 22 of 26 organizations yield in production, every source has a fixture, and a deliberately broken source turned `erroring` and failed the Actions job.
- Publish rule: an engine item whose title marks it as a test ("Test Hackathon - Didit KYC") waits for review. Hand-entered rows are exempt.
- M2.1a: `apps/web` scaffold (Next.js 16.4, React 19.3, Tailwind 4.3) that builds in `pnpm check`. M2.1 is split: tokens, fonts and layout (M2.1b) wait for the Claude Design pass so the data layer and API can start now.
- M2.3: data access layer in `apps/web/src/data` (opportunities with filters, search and keyset cursors; home sections and counts by deadline, kind and city; related items; events; the `/feed` query in two parts; organizations with source health; meta; status), tested against a separate `devspot_web_test` database. The registry sync moves to `@devspot/db/registry`, so the app's bundle never reads the registry from disk.
- M2.11: read-only API v1 (`/api/v1/opportunities`, `/opportunities/{slug}`, `/events`, `/organizations`, `/organizations/{slug}`, `/organizations/{slug}/opportunities`, `/meta`, `/openapi.json`) with CORS, CDN caching, a 60-a-minute per-IP limit and `{ error: { code, message } }` errors. OpenAPI 3.1 from the Zod schemas via zod-openapi, validated in tests and committed to `docs/schema/openapi.json`. `EventListParams`, `OrganizationListParams`, `MetaDto` and the page schemas join `@devspot/schema`. The `/api` docs page stays in M4.5. The `@devspot/db` client is now created on first use, so `next build` needs no `DATABASE_URL`.
- M2.12 (code): `POST /api/revalidate` (secret header; refreshes every ISR page and marks cached `/api/v1` responses stale by the `api-v1` CDN tag), called by `engine.yml` after each run once `REVALIDATE_SECRET` and `SITE_URL` exist. `apps/web/vercel.json` holds the install and build commands and the London function region. A read-only `web` database role for Vercel, granted in `grants.sql`. DTO URLs fall back to the Vercel production URL until a domain exists.
- `grants.sql` runs on any Postgres (each block guarded by its role; connect granted on the current database). The web tests apply it and run every data-layer query as the restricted `web` role, so a missing grant fails CI instead of production. `createClient(url)` joins `@devspot/db`.
- Rules extractor: a hybrid Nigerian item whose city is not in the dictionary ("Hybrid, Warri") goes to review instead of being stored as nationwide; nationwide needs the source to say so.
